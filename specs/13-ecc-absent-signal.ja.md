# ECC 不在時の劣化レビューシグナル

## ステータス

Approved

**オーナー:** product-manager / implementer
**対象リリース:** template v3.14.0

## 問題

ADR-012 は `code-reviewer` をメタレビュアーとして位置付け、言語固有の深みを ECC の `*-reviewer` エージェント (`typescript-reviewer`、`python-reviewer`、`go-reviewer` など) に委譲する設計とした。ADR-012 自身の Negative セクションは、意図的に未対処とした 2 つのコストを記録している: (1)「ECC を一度もインストールしないフォークは永続的に低品質なレビューで運用される」および (2)「ECC レビュアーとの契約は**バージョン管理されていない**。ECC が `typescript-reviewer` をリネームしたり、プロンプト契約を大幅に変更したりしても、ディスパッチャーの委譲行はサイレントに陳腐化する。対象エージェントの存在を確認する CI チェックが存在しない。」

現在、ECC 不在 / 劣化レビューのシグナルは次の 2 つのみである: `code-reviewer.md` 内のレビュー時判定行注記 (3 ケース委譲ルール、行 66–87 — レビューが実際に実行されたときのみ発火)、および `README.md` の `## Prerequisites` にある 1 つの静的な散文段落 (README を閲覧する人間向け。エージェントや CI のチェックポイントには伝播しない)。どちらも、「このフォークの `code-reviewer` 委譲テーブルは、オペレーター環境に存在しない可能性のある ECC エージェントを参照しており、言語固有のレビュー層がサイレントに弱体化する」という*常時的な*劣化レビューのポスチャーを、確定的な非レビュー時チェックポイントで検出可能にするものではない。また `code-reviewer.md` の委譲テーブル (9 行の `manifest → ECC レビュアー` マッピング) は、参照するエージェント名と乖離しても何も検知されない — これはまさに ADR-012 が名指しして未対処のまま残した「行がサイレントに陳腐化する」障害である。

## ゴール

- 常時的な劣化レビューのポスチャーを、コードレビューを最初に実行することなく観測可能な、明示的かつ確定的なシグナルにする — ADR-012 が記録した「対象エージェントの存在を確認する CI チェックが存在しない」/「行がサイレントに陳腐化する」ギャップを、テンプレート環境が許す範囲で埋める。
- テンプレートリポジトリ自身の CI においてシグナルが正しく機能するようにする。テンプレートでは ECC はリポジトリ内に存在しない (ECC はユーザーレベル `~/.claude/` にインストールされ、リポジトリの外側にある)。シグナルは通常の ECC 不在 CI 条件に対して「何かが壊れている」という誤った失敗を生じさせてはならない; ポスチャーを報告し、通常ケースに対してビルドを失敗させない。
- このマイルストーンが所有する問いと、4 つの既存ディテクターおよび `code-reviewer.md` と `README.md` が既に所有するレビュー時 / ランタイムシグナルとの間に MECE 境界を確立し、将来のマイルストーン作成者がスコープを明確にルーティングできるようにする。
- `code-reviewer` の 3 ケース委譲ルールとその保守的な「デフォルトでケース 3 を選択」ポスチャーを変更しない。ADR-012 のランタイム動作は正しい; #13 は常時的な非レビュー時シグナルを追加するものであり、レビュー時のシグナルを変更するものではない。
- フォークメンテナーまたはエージェントが関連チェックポイントで既に参照するアーティファクトにシグナルを配置し、新しい常時読み取りファイルや既存チェックポイントが要求するもの以上の第 3 の参照を要求しない (正確な配置とメカニズムは architect に委ねる; リスク R-01 参照)。

## ゴール対象外

- パス解決、ADR テキスト参照、または `.claude/`-ルートのパス言及の確認 — それはマイルストーン #04 (`check-dangling-refs.sh`、ADR-015) が所有する。
- Roadmap 双方向リンク契約またはステータスグリフの適合性の確認 — それはマイルストーン #05 (`check-roadmap-drift.sh`、ADR-017) が所有する。
- EN/JA 見出しツリーパリティの確認 — それはマイルストーン #06 (`check-bilingual-parity.sh`、ADR-018) が所有する。
- カバレッジしきい値の強制 — それはマイルストーン #12 (`coverage-gate.yml`、ADR-019) が所有する。
- ECC がオペレーターの `~/.claude/` に*インストールされているかどうか*の検出。それはリポジトリ内部から、および CI から構造的に不可能である (ECC はユーザーレベルであり、リポジトリ外)。#13 はオペレーター環境のファイルシステムイントロスペクションを試みてはならない; そうすることは、`code-reviewer.md` 行 84–87 が明示的に禁止している「エージェントはファイルシステムをイントロスペクトしない。不明な場合はデフォルトでケース 3 を選択する」という信頼性の低いランタイムイントロスペクションを再現することになる。
- `code-reviewer` の 3 ケース委譲ルール、委譲テーブルのセマンティクス、または「不明な場合はデフォルトでケース 3 を選択」という保守的ポスチャーの変更 — ADR-012 のランタイム契約は正しく、このマイルストーンのスコープ外である。
- ECC の言語固有レビュアーを `.claude/agents/` にベンダリングして依存を解消する。それは ADR-012 が意図的に却下した Counter-proposal (Alternative B); #13 は*既存の*依存の劣化ポスチャーを可視化するものであり、依存を解消するものではない。
- テンプレートの通常の ECC 不在条件に対してテンプレート自身の CI を失敗させる。シグナルはポスチャーの報告であり、通常ケースに対するハードゲートではない。(本当の内部不整合 — 例: 委譲テーブルがテンプレート自身の契約と矛盾する名前を参照している — に対して追加でハード失敗できるかどうかは、architect に委ねる構造的決定; リスク R-01 参照。)
- 正確なメカニズム (新しいディテクタースクリプト + ワークフロー、既存ディテクターの拡張、ドキュメント / 規約ステートメント、エージェントプロンプト変更、またはその組み合わせ) および新しい ADR-020 か ADR-012 修正かの指定。それは architect の構造的決定である (リスク R-01 参照)。
- 4 つの既存ディテクタースクリプト (`.claude/meta/scripts/check-dangling-refs.sh`、`check-roadmap-drift.sh`、`check-skill-invariants.sh`、`check-bilingual-parity.sh`) またはそのテストスイートの変更。#13 はそれらのアーティファクトに変更を加えない。

## 受け入れ基準

- **Given** フォークメンテナーまたはエージェントが #13 がシグナルを配置するアーティファクト (正確なアーティファクトとセクションは architect が決定) を参照している **when** レビューポスチャーを探す **then** 常時的な劣化レビューポスチャーが明示的に述べられている: `code-reviewer` の言語固有層は ECC の `*-reviewer` エージェントに委譲し、ECC 不在時に劣化する (テンプレートのクロスカッティングチェックのみ) — コードレビューを最初に実行することなく検出可能。

- **Given** シグナル **when** 読者が `code-reviewer.md` 行 66–87 (3 ケース委譲ルール) と比較する **then** #13 のシグナルが*常時的な非レビュー時*ポスチャーシグナルであり、3 ケースルールが*レビュー時ランタイム*シグナルであることが明確である — 両者は補完的であり重複しておらず、#13 のテキストは 3 ケースのメカニズムを再述しない。

- **Given** テンプレート自身のリポジトリが CI を実行している **when** #13 のシグナルが評価する **then** ECC がリポジトリ内に存在しないという通常の期待される条件に対して CI 失敗を生じさせない (ECC は構造的にユーザーレベル)。シグナルは期待されるケースに対してポスチャーを報告する; そのケースに対してビルドをハード失敗させない。

- **Given** `code-reviewer.md` の委譲テーブル **when** #13 のメカニズムがそれを評価する **then** メカニズムが、委譲テーブル行がテンプレート自身の委譲契約と矛盾する ECC エージェント名を参照しているドリフトを検出する (ADR-012 が名指しした「行がサイレントに陳腐化する」障害)、選択されたメカニズムがオペレーター環境イントロスペクションなしに内部整合性を判断できる範囲で。

- **Given** #13 のシグナル **when** オペレーター環境のファイルシステムイントロスペクションについて検査する **then** それを一切実行しない — #13 が ECC が `~/.claude/` にインストールされているかどうかを検出しようとしないことを確認し、信頼性の低いランタイムイントロスペクションを禁止する `code-reviewer.md` 行 84–87 と整合している。

- **Given** `code-reviewer.md` の 3 ケース委譲ルールと「不明な場合はデフォルトでケース 3 を選択」ポスチャー **when** レビュアーが #13 出荷後にそれらをdiffする **then** 変更されていない — #13 が常時シグナルを追加し ADR-012 のランタイム契約を変更しなかったことを確認。

- **Given** シグナルの配置 **when** フォークメンテナーが採用時にレビューポスチャーを評価する **then** ポスチャーが関連するチェックポイントで既に必須となっているファイルを開かずに遭遇できる (新しい常時読み取りファイルなし; そのチェックポイントが既に義務付けているもの以上の第 3 の参照なし — 正確な共同配置は architect の決定)。

- **Given** #13 のメカニズム **when** 将来のマイルストーン作成者がスコープルーティングについてそれを検査する **then** #13 (劣化レビューポスチャー / 委譲テーブル整合性)、#04 (パス解決)、#05 (Roadmap 構造)、#06 (EN/JA パリティ)、#12 (カバレッジしきい値)、および `code-reviewer.md`/`README.md` が既に所有するレビュー時シグナルとの MECE 境界が明確である — #13 はそれらのどれも所有しない問いを所有する。

## 主なインタラクション

1. **`code-reviewer.md` 行 66–87 (3 ケース委譲ルール) とのインタラクション。** そのルールは、*レビュー時*に「このレビューで委譲は成功したか / 失敗したか / 試みられなかったか、またこのレビューは劣化しているか?」という問いに答える。#13 は先行する*常時的な*問いに答える: 「このフォークはそもそも劣化レビューポスチャーで運用されているか、また委譲テーブルは内部的に整合しているか?」両者は補完的である。#13 のシグナルは 3 ケースのメカニズムを再述してはならない; レビュー時の問いについては `code-reviewer.md` に読者を誘導すべきである。

2. **`README.md` `## Prerequisites` (行 11–24) とのインタラクション。** その段落は、README を閲覧する人間のために散文でポスチャーを述べている。エージェントや CI のチェックポイントには伝播しない。#13 はポスチャーが実行可能なチェックポイントで検出可能でないというギャップを埋める — architect の配置決定 (R-01) が、ギャップがディテクターで埋められるか、エージェントプロンプト / CLAUDE.md ステートメントで埋められるか、既存ディテクターの拡張で埋められるか、またはその組み合わせか、および既存の README 散文との関係を決定する。

3. **ADR-012 (ディスパッチャーとしての Code Reviewer) とのインタラクション。** ADR-012 の Negative セクションは「対象エージェントの存在を確認する CI チェックが存在しない」および「委譲行がサイレントに陳腐化する」を未対処のコストとして明示的に記録しており、その Counter-proposal (Alternative B、レビュアーをローカルにベンダリング) は意図的に却下された。#13 は*記録されているが未対処のコスト*を対処する; 却下された Counter-proposal を再検討せず、ECC 依存を解消しない。#13 の解決策が新しい ADR-020 か ADR-012 修正かは architect の判断である (R-01)。

4. **ディテクターファミリー (#04/#05/#06) および #12 とのインタラクション。** architect の選択メカニズムが新しいディテクターであれば、#04 が確立し #05/#06 が踏襲した `check-*.sh` ファミリーに加わる。それが正しい形状であるか、ADR-018 Alternative-B 判別子を必要とする新しい MECE 契約境界を引くかどうかは、architect の構造的決定である。#13 の Non-goals は、メカニズムに関わらず #13 が 4 つの既存ディテクターやそのスイートを変更しないことを固定する。

5. **ADR-014 §(d) MECE 境界とのインタラクション。** ADR-014 の §(d) MECE テーブルは #04、#05、#09、#10、#11 を名指しする (ADR-019 の推論により #12 について修正済み); #13 のスロットを事前予約**しない**。#13 は事前予約された「ドキュメント / 規約」スロットを占有しない — architect が ADR-018 Alternative-B 判別子を適用する際に考慮すべき実質的な区別 (同一の観察を持つ #12 の `specs/12-coverage-ci-gate.md` R-01 をミラー)。

6. **構造的 HOW は architect に委ねる。** #13 が (a) `code-reviewer.md` の委譲テーブルの内部整合性を確認する `workaround-check.yml`/`coverage-gate.yml` に類似した新しいデフォルトオフディテクタースクリプト + ワークフロー、(b) 適切なチェックポイントで常時ポスチャーを検出可能にする `code-reviewer.md`/`README.md`/CLAUDE.md に共同配置されたドキュメント / 規約ステートメント、(c) 既存ディテクターの拡張、または (d) その組み合わせとして出荷するかどうか — すべて architect の forthcoming decision に委ねる。architect は ADR-018 Alternative-B 判別子を逐語的に適用する: *#13 が NEW ディテクター + NEW MECE 契約境界 + NEW キーイング / メカニズムを導入する (⇒ 新しい ADR-020) か、それとも ADR-012 の既に記録されているが未対処の Negative の consequence-clarification / 拡張である (⇒ ADR-012 修正)?* ADR-020 は次の未使用 ADR 番号 (016/017/018/019 は #03/#05/#06/#12 で消費済み; #07–#11 の ADR-014 修正は新しい番号を消費しない)。architect が決定する; 本 Spec は決定しない。

## メトリクス

- **先行指標:** #13 出荷後、フォークメンテナーまたはエージェントがコードレビューを最初に実行することなく確定的なチェックポイントで常時的な劣化レビューポスチャーに遭遇できる — 配置されたシグナルから検証可能。
- **先行指標:** テンプレート自身の `main` ブランチの CI ジョブがマイルストーン出荷直後に通過する — 期待される ECC 不在条件に対して新たな失敗ジョブが導入されない (AC-3)、テンプレート CI を実行することで検証可能。
- **先行指標:** 4 つの既存ディテクタースクリプトまたはそのテストスイートファイルへのゼロ変更 (Non-goals)、それらのアーティファクトに対して `git diff` で検証可能。
- **遅行指標:** 常時的な劣化レビューポスチャーについてメンテナーが情報に基づいた決定をすることなくサイレントに劣化レビューで運用する派生リポジトリの削減、時間の経過によるフォーク監査を通じて観察可能。

## リスクとオープンクエスチョン

### リスク R-01: architect に委ねた構造的決定 — シグナルメカニズム、配置、ADR 戦略

**説明。** 本 Spec はシグナルが達成しなければならない*こと* (常時的な劣化レビューポスチャーが確定的な非レビュー時チェックポイントで検出可能; 委譲テーブルの内部整合性ドリフトが捕捉される; オペレーター環境イントロスペクションなし; 期待される ECC 不在ケースに対して CI 失敗なし; 3 ケースランタイムルールが変更されない) と適合したシグナルの受け入れ基準を述べる。構造的な*どのように*を明示的に委ねる: メカニズムが新しいデフォルトオフディテクタースクリプト + ワークフロー、ドキュメント / 規約ステートメント、既存ディテクターの拡張、エージェントプロンプト / CLAUDE.md 変更、またはその組み合わせかどうか; フォークメンテナー / エージェントが追加ファイル読み取りなしに関連チェックポイントでシグナルに遭遇できるようにシグナルが配置される場所; および解決策が新しい ADR-020 か ADR-012 修正を必要とするかどうか (ADR-018 Alternative-B 判別子を適用: NEW ディテクター + NEW MECE 契約境界 + NEW キーイング / メカニズム ⇒ 新しい ADR-020; ADR-012 の既に記録されているが未対処の Negative の consequence-clarification / 拡張 ⇒ ADR-012 修正; ADR-019 は最後に消費された ADR 番号、ADR-020 は未使用)。これは `specs/12-coverage-ci-gate.md`、`specs/11-verification-domain-opt-in-guidance.md`、`specs/10-spec-adr-directory-pinning.md`、および以前の構造的 Spec で使用された R-01 パターンをミラーする。

**architect に明示的に渡された緩和制約。** architect の forthcoming decision は以下を指定しなければならない: (a) 正確なメカニズムとシグナルが着地する正確なファイル / セクション (フォークメンテナーまたはエージェントがそのチェックポイントで既に必須となっているファイルを開かずに、劣化ポスチャーが実行可能なチェックポイントでそれに遭遇できるように); (b) 解決策が新しい ADR-020 か ADR-012 修正かどうか (Alternative-B 判別子)、句ごとの推論を記録; (c) メカニズムがディテクターの場合、オペレーター環境イントロスペクションなしに委譲テーブルの内部整合性をどう判断するか、およびテンプレート自身の期待される ECC 不在 CI 条件においてどのようにグリーンを保つか; (d) #13 が #04/#05/#06/#12 およびレビュー時シグナルに対して MECE 境界のどこに位置するかの明示的な記述、および新しい契約パーティションを追加するかどうか。その決定が存在するまで、本 Spec で特定されたギャップ (劣化ポスチャーがレビュー後判定行または README 散文経由でのみ検出可能; 委譲行がサイレントに陳腐化する可能性がある) が運用状態のままである。

### リスク R-02: ECC 依存の解消へのスコープクリープ

**説明。** 将来の作成者またはレビュアーが「劣化ポスチャーを可視化する」と「ECC レビュアーをローカルにベンダリングして劣化ポスチャーを解消する」を混同するかもしれない。後者は ADR-012 が意図的に却下した Counter-proposal (Alternative B) である。

**緩和策。** Non-goals と主なインタラクション 3 が境界を明示的に引く: #13 は*既存の*依存の劣化ポスチャーを可視化する; 依存を解消しない。将来の作成者がレビュアーのベンダリングを提案した場合、正しい対応はそれを ADR-012 の Counter-proposal の再検討として独自のマイルストーンにルーティングすることであり、#13 に折り込むことではない。

### リスク R-03: オペレーター環境イントロスペクションへのスコープクリープ

**説明。** 「ECC 不在時にシグナルを出す」は「ECC が `~/.claude/` にインストールされているかどうかを検出する」と誤読される可能性がある。その検出はリポジトリからおよび CI からは構造的に信頼性のある形では不可能であり、`code-reviewer.md` 行 84–87 はそれが要求する信頼性の低いランタイムイントロスペクションを明示的に禁止している。

**緩和策。** AC-5 は非イントロスペクション制約について具体的に検証可能である; Non-goals はそれを成文化する。シグナルは*常時ポスチャーおよび委譲テーブルの内部整合性*についてであり、オペレーターのマシンのライブプローブではない。implementer はメカニズムをリポジトリ外を決して読まないようにフレーム化しなければならない。

## スコープ対象外

- 4 つの既存ディテクタースクリプト (`check-dangling-refs.sh`、`check-roadmap-drift.sh`、`check-skill-invariants.sh`、`check-bilingual-parity.sh`) またはそのテストスイートの変更 — #13 はそれらのアーティファクトに変更を加えない。
- `code-reviewer` の 3 ケース委譲ルール、委譲テーブルのセマンティクス、または「不明な場合はデフォルトでケース 3 を選択」ポスチャーの変更 — ADR-012 のランタイム契約は正しく、スコープ外である。
- ECC がオペレーターの `~/.claude/` にインストールされているかどうかの検出 — リポジトリ / CI からは構造的に不可能であり `code-reviewer.md` 行 84–87 により禁止されている。
- ECC の言語固有レビュアーを `.claude/agents/` にベンダリングする — ADR-012 が意図的に却下した Counter-proposal; #13 のスコープ外。
- JA 兄弟 (`specs/13-ecc-absent-signal.ja.md`) の作成 — それは technical-writer の責任であり、実装後に順序付けられており、見出しツリーパリティは Roadmap #06 が所有する。
- ADR-012 の Decision またはその却下された Counter-proposal の変更 — #13 は ADR-012 の記録されているが未対処の Negative を対処する; ADR-012 の Decision を争わない。
- GitHub Actions 以外の CI プロバイダーへの新しいスキャフォールドの変換。
