# ADR-019: CI カバレッジゲート (80% ハードチェック) — 事前計算済みパーセンテージ入力、default-off シングルスイッチポスチャー、信頼できる唯一の情報源によるしきい値バインディング、ADR-014 §(d) が事前予約しない新しい MECE 分割

## ステータス

Accepted — 2026-05-18

## 背景

テンプレートの `.claude/CLAUDE.md` `## Testing Requirements` セクションは
書かれたルールとして「Minimum 80% test coverage」を定める。
これを強制する CI ジョブは存在しない。`.github/workflows/ci-base.yml` は
派生リポジトリから `test-command` 入力を受け取りそのテストを実行するが、
しきい値を課さず、カバレッジメトリクスを出力せず、カバレッジが 80% を
下回ってもビルドを失敗させない。派生リポジトリは今日 10% のカバレッジで
出荷しても CI を通過できる。`specs/12-coverage-ci-gate.md` が権威的な
スコープである — 8 つの受け入れ基準、4 つのリスク、Non-goals。
本 ADR は Spec が `architect` に明示的に委ねる **構造的** 決定を記録する
(Spec リスク R-01 (a)–(e)、R-02、R-03、R-04、Key-interaction 6):
CI の構造的形態、アクティベーションポスチャーとその単一制御点機構、
しきい値の信頼できる唯一の情報源へのバインディング、言語非依存の
フォーク可能性入力契約、そして新規 ADR か amendment かの決定。
Spec はこの決定を ADR-019 と指名し、ディスクリミネーターを architect に
逐語的に渡す。本 ADR がそれを閉じる。

本マイルストーンは **第 4 のディテクターではない**。#04
(`check-dangling-refs.sh`、ADR-015) は相互参照の *解決* を所有する。
#05 (`check-roadmap-drift.sh`、ADR-017) は Roadmap *インデックス
一貫性* を所有する。#06 (`check-bilingual-parity.sh`、ADR-018) は
EN↔JA *翻訳パリティ* を所有する。3 つのいずれも — また #11 の
ドキュメント/規約ガイダンスも — *CI 時のカバレッジしきい値強制* 契約を
所有しない。#12 はその契約を新しい分割として導入する。重複するファイルを
スキャンするチェック間で ADR-017 §2 と ADR-018 §5 が MECE-by-contract
境界を引いたのと同じ推論が、ここでは分割レベルで適用される: #12 の
チェックは *まったく異なる入力* (リポジトリの Markdown 成果物ではなく、
派生リポジトリの事前計算済みカバレッジパーセンテージ) をスキャンするため、
境界は #04/#05/#06 の三方向契約分割よりさらにクリーンである —
曖昧化すべき共有成果物がない。

設計を制約する 5 つのハード制約は交渉不可能である:

1. **テンプレートにアプリケーションコードがない (Spec R-03、AC-5)。**
   テンプレートリポジトリの唯一の実行可能成果物は bash ディテクター
   スクリプトとそのテストスイートであり、測定すべきアプリケーション
   カバレッジは存在しない。ここで作られるカバレッジゲートは
   テンプレート自身の bash に対して走るチェックではなく
   **フォーク可能なスキャフォールド** である — `ci-base.yml`
   (パラメータ化された `workflow_call`) と `workaround-check.yml`
   (default-off シングルスイッチスキャフォールド) がすでに占める
   構造的ポスチャーそのものである。ゲートはテンプレート自身に対して
   **green-by-construction または正しく不活性** でなければならず、
   カバレッジ免除も `ref-allow` 風の抑制も green を保つために
   必要としてはならない。
2. **80% という数値の信頼できる唯一の情報源 (Spec R-02、AC-2、
   AC-8)。** しきい値の権威的宣言は `.claude/CLAUDE.md`
   `## Testing Requirements` (「Minimum 80% test coverage」) である。
   スキャフォールドは権威的宣言からドリフトしうる第 2 の競合する
   数値リテラルを **導入してはならない**。将来のしきい値変更は
   ちょうど 1 か所の編集を要求しなければならない。
3. **言語非依存のフォーク可能性 (Spec R-04、AC-3)。** カバレッジ出力
   形式は言語とツールチェーンによって異なる (`coverage.py` XML、Go
   `coverprofile`、`lcov.info`、JaCoCo XML、`llvm-cov`、Swift JSON、…)。
   テンプレートは N 個の形式を **パースしてはならない**。派生
   リポジトリが自身の事前計算済みカバレッジパーセンテージを供給する。
   `ci-base.yml` の `workflow_call` `test-command` 入力パターンを
   ミラーする。
4. **`ci-base.yml` の `test-command` 契約は不変 (Spec
   Key-interaction 1)。** 既存の `test-command` 入力とその
   しきい値なし挙動は、カバレッジゲートにオプトインしていない派生
   リポジトリにとって **同一のまま** でなければならない。ゲートは
   付加的であり、テスト実行契約の変更ではない。
5. **既存ディテクターレイヤーへのスコープ漏出なし (Spec AC-6、
   Key-interaction 5)。** 4 つのディテクタースクリプト
   (`check-dangling-refs.sh`、`check-roadmap-drift.sh`、
   `check-skill-invariants.sh`、`check-bilingual-parity.sh`) と
   その 3 つのテストスイートは本マイルストーンで **変更されない**。

6 番目の力は **ADR-018 Alternative-B ディスクリミネーター** 自体であり、
Spec R-01 と Key-interaction 6 によって architect に渡される。
ADR-018 の Alternatives テーブル行 B は「既存 ADR の amendment に
折り込む」対「新規 ADR」を 3 部構成テストで分類する: **新しい
ディテクター/CI ハードチェック + 新しい MECE 契約境界 + 新しい構造的
キーイング** を導入するマイルストーンは ECC 先例の「新しい構造的決定」
半分であり、ADR-015、ADR-017、ADR-018 がそれぞれ自己分類したのと
まったく同じく新規 ADR を要する。本 ADR はそのディスクリミネーターの
適用 (決定 5) を、決定の引用可能なホームとして記録する。
却下された反対の正しい状態は非存在である (反対提案セクション参照)。

7 番目の力は **#04 dangling-reference detector** 自体であり、現在
アクティブな CI である。本 ADR ファイルは #04 ディテクターの Check-1
スコープ内にある。当時まだ書かれていなかった
`.github/workflows/coverage-gate.yml`
および計画中の `.claude/meta/scripts/` カバレッジしきい値ヘルパーへの
言及は Check 2 に該当するが、ADR ファイルは #04 ディテクター自身の
文書化されたスコープ決定 (ADR ファイルは歴史的記録であり、`.claude/`
ルートのパスは Check-2 で検証されない) によって除外される。これは
ADR-015、ADR-016、ADR-017、ADR-018 がディテクターの相互作用を列挙した
方法をミラーする明示的な設計インプットとして扱われる。

## 決定

カバレッジゲートは **`.github/workflows/coverage-gate.yml` という単一のスタンドアロンでフォーク可能なワークフロー**
であり、`.github/workflows/ci-base.yml` の変更としてではなく
それと *並んで* 作成され、テンプレート自身の CI が既定で不活性 green に
なり派生リポジトリがちょうど 1 つの変更でオプトインできるよう
**シングルスイッチの背後で default-off** で実行される。それは派生
リポジトリの **事前計算済みカバレッジパーセンテージ** を
`workflow_call` 入力として受け取り (テンプレートはカバレッジ形式を
パースしない)、カバレッジがしきい値を下回るとき非ゼロ終了と測定
カバレッジ・しきい値の両方を指名する人間可読メッセージでビルドを
失敗させ、80% という数値を **再宣言するのではなく信頼できる唯一の
情報源から参照する**。それは **新しい MECE 分割** —
CI 時のカバレッジしきい値強制 — を導入する。ADR-014 の §(d) MECE
テーブル (約 1800 行目。#04/#05/#09/#10/#11 を指名するが #12 は
**指名しない**) はそれを **事前予約しない**。だからこれは
**新規 ADR-019** であり、ADR-014 amendment でも ADR-010 amendment でも
ない。

本 ADR はまず **設計のみ** の記録として作成された。実際の
ワークフローファイル、アクティベーション設定成果物、しきい値抽出機構、
green-by-construction テンプレート保証、テストは **後続の実装セッションで
着地した** — #03/ADR-016、#05/ADR-017、#06/ADR-018 がそれぞれ踏襲した
意図的な二セッション分割 (決定してから実装) であり、単一セッション崩壊の
**反対** である。ステータスは、その実装セッションが成果物を出荷し
品質ゲートが green を通過したとき **Proposed → Accepted** に移行した:
決定が先に記録され、次いで忠実な実装によって検証された。

### 1. CI の構造的形態 — スタンドアロンのフォーク可能ワークフロー、`ci-base.yml` の変更ではない

ゲートは独自のファイル
`.github/workflows/coverage-gate.yml`
として出荷され、`roadmap-drift-check.yml` と `workaround-check.yml` が
別のワークフローに接ぎ木されたステップとしてではなく独自のファイルとして
出荷されるのと同じく `workflow_call` インターフェースを公開する。
それは `ci-base.yml` への編集 **ではない**。

推論は ADR-017 §2 が #04↔#05 境界に適用し ADR-018 §5 が三方向に拡張した
locality-of-behavior / 1 契約 1 オーナー規律である: `ci-base.yml` は
1 つの契約 — 「派生リポジトリの `test-command` を実行する」 — を
所有する。カバレッジゲートは *異なる* 契約 — 「結果のカバレッジが
しきい値以上か?」 — を所有する。しきい値チェックを `ci-base.yml` に
折り込むと 2 つの契約が 1 つの名前の 1 ジョブに乗り、ADR-017 §2 が
Check-4 ケースで却下し ADR-018 §5 が三方向ディテクター分割で却下した
まさに「どの契約が失敗したか?」の曖昧さを再現する。さらに、
しきい値なしのテスト実行のために `ci-base.yml` を使うすべての派生
リポジトリにオプトインしていないしきい値の意見を継承させ、ハード
制約 4 (Spec Key-interaction 1: `test-command` 挙動はオプトインして
いないリポジトリで不変でなければならない) を破る。スタンドアロンの
`workflow_call` ファイルは 2 つの契約を 2 つのオーナーの 2 つの
ファイルに保ち、`ci-base.yml` をバイト不変に残す。

`.claude/meta/scripts/` 配下の小さなしきい値抽出ヘルパーはこの設計で
**許可されるが必須ではない** — 80% 信頼できる唯一の情報源バインディング
(決定 3) がインラインのワークフローステップで実現されるか小さな
sourced ヘルパーで実現されるかは `implementer` の詳細であり、
帰結 → 中立に記録され、ここで固定されない。ヘルパーが作られる場合
そのパスは既存の `.claude/meta/scripts/check-*.sh` 命名ファミリーの下で
`implementer` が選ぶ。本 ADR はテンプレートが **カバレッジレポート
形式を一切パースしない** こと (決定 4) を固定し、bash を固定しない。

### 2. アクティベーションポスチャー — default-off シングルスイッチ、`workaround-check.yml` 先例

Spec (R-01、Key-interaction 2/3、AC-4) は 3 つの候補ポスチャーを
指名し、architect に 1 つを選びその 3 つの先例に対して正当化するよう
求める:

- **always-on** (ADR-015 subject-matter-presence ルール、
  `roadmap-drift-check.yml` のように)、
- **default-off-single-switch** (`workaround-check.yml`: トラッカー
  YAML 内の `enabled: true`)、
- **repository-variable-gated** (CodeQL #02: `CODEQL_ENABLED=true`)。

**選択: default-off シングルスイッチ**、`workaround-check.yml` の
直接の類似。決定的なディスクリミネーターはハード制約 1 (Spec
R-03/AC-5) である: テンプレートリポジトリは **アプリケーションコードを
持たず測定すべきカバレッジを持たない**。ADR-015 subject-matter-presence
ルールはチェックを always-on に置く **のはその対象事項がすべての
フォークで常時存在する構造的契約である場合に限る** — Roadmap ドリフトと
EN/JA パリティが適格なのは Roadmap と bilingual 成果物がテンプレート
自身に存在するからである。アプリケーションコードカバレッジは逆である:
それはテンプレートから構造的に **不在** であり、派生リポジトリが
アプリケーションコードを追加して初めて存在する。したがって always-on は
本マイルストーンで subject-matter-presence テストに **失敗** する —
対象事項がテンプレートに存在しない — そしてゲートが「カバレッジ成果物
なし」を検出して green を保つためだけにゼロ終了することを要求する。
default-off はその特殊ケースを完全に除去する: スイッチがオフだと
ジョブはテンプレートに対してまったく走らないので AC-5 (「新しい
失敗ジョブなし … カバレッジ免除や `ref-allow` 風抑制を要求してはならない」)
が不活性検出分岐ではなく **構造的に** 満たされる。

default-off-single-switch は single-point-of-control 基準 (AC-4) で
repository-variable-gated (CodeQL #02) より優先される: リポジトリ
変数は GitHub Settings UI に存在し、ファイルツリーの **外** にあり、
リポジトリを読むレビュアーには見えず PR で diff できない。
`workaround-check.yml` 先例はスイッチを **リポジトリ内、1 ファイル、
1 キー** に保つ — diff 可能、レビュー可能、grep 可能 — それが AC-4 の
「ちょうど 1 か所に文書化されちょうど 1 つの変更で切り替わる」の
より強い実現である。CodeQL #02 の repository-variable ポスチャーが
CodeQL に正しいのは CodeQL が GitHub プラットフォームのセキュリティ
機能でその自然な制御プレーンが GitHub Settings だからである。
カバレッジしきい値はその自然なホームがリポジトリであるリポジトリ
ポリシー決定である。

**単一制御点** はちょうど 1 つのリポジトリ内アクティベーション設定
ファイル内のちょうど 1 つのキー (`workaround-check.yml` /
`.github/workaround-tracker.yml` の形: 単一の `enabled: true` ブール値)
であり、ワークフローが CI 実行時に読む。ワークフロー本体に
**第 2 の `if: false` ガードはなく、第 2 の設定キーはなく、リポジトリ
変数はない** — 1 つのスイッチ、1 か所、AC-4 / ADR-002 シングルスイッチ
規律。アクティベーション設定の正確なファイル名と YAML キー名は決定 1 の
ファミリー規約の下での `implementer` の詳細である。本 ADR は
*ポスチャー* (default-off) と *単一制御点不変条件* (ちょうど 1 つの
ブール値、リポジトリ内、diff 可能) を固定し、bash もファイル名も
固定しない。

### 3. 信頼できる唯一の情報源 — 80% という数値は参照され、決して再宣言されない

しきい値の権威的宣言は `.claude/CLAUDE.md` `## Testing Requirements` —
リテラル行「Minimum 80% test coverage」 — であり、そうあり続ける
(Spec R-02、AC-2、AC-8; ハード制約 2)。スキャフォールドはドリフト
しうる第 2 の `80` 数値リテラルを **ハードコードしてはならない**。

ここで固定される構造的要件 (正確な awk/grep は `implementer` のもの、
ADR-015/016/017/018 が使った中立セクション規律): 強制される
しきい値は **CI 実行時に `.claude/CLAUDE.md`
`## Testing Requirements` から権威的行を読むことで導出され**、
ワークフローや設定ファイルに独立したリテラルとして書かれない。
具体的には、ワークフロー (または小さな sourced ヘルパー、決定 1) が
`## Testing Requirements` の「Minimum NN% test coverage」行から整数を
抽出し、派生リポジトリの供給したカバレッジパーセンテージを
*その* 抽出値と比較する。アクティベーション設定ファイル (決定 2) は
**オン/オフスイッチのみ** を持つ — 設定ファイルの数値はまさに R-02 が
禁じる第 2 のドリフトする宣言になるので、意図的に数値を **持たない**。
将来のしきい値変更 (80 → 85) はそのとき `## Testing Requirements` への
1 行編集とそれ以外なしになる。CI 強制は第 2 の編集ゼロで自動的に
追従する。これは ADR-017 §4 が主張不在免除に義務付け ADR-018 §1 が
convention-presence キーイングに義務付けた「ルールを成果物にキーイング
し、成果物から読む」と同じ規律であり、ここではしきい値の値に適用される。

抽出が権威的行を見つけられない場合 (例: フォークが
`## Testing Requirements` を削除した) ゲートは静かに通過するのではなく
**明示的メッセージで fail-closed** する (「`.claude/CLAUDE.md`
`## Testing Requirements` に権威的 80% 宣言が見つからない」) —
ディテクターファミリーが取るのと同じ fail-closed 方向であり、
削除された契約は不可視ではなく大声になる。(これは抽出器を
`## Testing Requirements` 行形状に結合する。その結合は帰結 → ネガティブ
に単一の権威的行に絞って記録される。)

### 4. 言語非依存のフォーク可能性 — `workflow_call` 入力としての事前計算済みパーセンテージ

スキャフォールドは派生リポジトリの **事前計算済みカバレッジ
パーセンテージ** を `workflow_call` 入力として受け取り (Spec R-04、
AC-3; ハード制約 3)、`ci-base.yml` の `workflow_call` `test-command`
入力パターンをミラーする。派生リポジトリは自身の言語固有カバレッジ
ツールを自身のジョブで実行し、自身のツールチェーンにネイティブな
手段 (`coverage.py`、`go tool cover`、`lcov`、JaCoCo、`llvm-cov`、…)
で単一のプロジェクトレベルパーセンテージを計算し、その **数値** を
渡し込む。テンプレート所有のワークフローは **カバレッジレポート形式を
一切パースしない** — 整数/小数パーセンテージとしきい値 (決定 3) を
受け取り 1 つの数値比較を行う。

ここで固定される入力契約 (正確な入力名/型は `implementer` のもの):
測定カバレッジパーセンテージを数値として運ぶ 1 つの必須 `workflow_call`
入力、呼び出し元が供給。しきい値は呼び出し元入力 **ではない**
(信頼できる唯一の情報源から来る、決定 3) ので呼び出し元は低い
しきい値を渡してゲートを弱められない。これはテンプレートをあらゆる
カバレッジ形式パーサーから自由に保ち (Spec R-04 が守るフォーク可能性
ゴール)、しきい値の権威をテンプレート側に保つ (Spec R-02 が守る
単一情報源ゴール) — 2 つの制約が同じ入力形状決定で満たされる:
呼び出し元が *測定* を供給し、テンプレートが *しきい値* を所有する。

### 5. MECE 境界 — ADR-014 §(d) が事前予約しない新しい分割

#12/ADR-019 は **「プロジェクトのテストカバレッジは 80% 最小値を
満たすか、CI 時に強制されるか?」** という問いを所有する。これは
**新しい分割** であり、既存のすべての所有された問いと区別される:

| オーナー | 所有する問い | スキャンする入力 |
|---|---|---|
| #04 `check-dangling-refs.sh` (ADR-015) | 散文/パス参照は実在ファイル/ADR に **解決** するか? | リポジトリ Markdown 成果物 |
| #05 `check-roadmap-drift.sh` (ADR-017) | **双方向 Roadmap インデックス契約** が保たれすべての Status グリフが整形式か? | `.claude/CLAUDE.md` + ADR |
| #06 `check-bilingual-parity.sh` (ADR-018) | **EN↔JA ペアが構造的に一致** するか (見出しツリー、全角括弧、存在)? | ペアの `.md`/`.ja.md` 成果物 |
| #11 (verification-domain opt-in ガイダンス、ADR-014 §(d)) | どのプロジェクト特性下でフォークは implementation/design verification ドメインを **有効化** すべきか? | ドキュメント/規約 (ディテクターなし) |

欠陥はちょうど 1 人のオーナーにマッピングされる: *壊れたポインター*
は #04 のもの。*Roadmap インデックス不整合* は #05 のもの。
*構造的に乖離した EN/JA ペア* は #06 のもの。
*verification-domain 有効化ガイダンスの問い* は #11 のドキュメント
関心事。*CI 時のしきい値以下のカバレッジ* は #12 のものであり
**#12 のみ** のものである。ここでの境界は #04/#05/#06 三方向契約分割
(ADR-018 §5) よりさらにクリーンである: あの 3 つは重複する Markdown
成果物をスキャンし分割を曖昧化解消のため *契約* で引かねばならなかった。
#12 は **まったく異なる入力** (リポジトリ成果物ではなく実行時供給の
カバレッジ数値) をスキャンするので曖昧化解消すべき共有サーフェスが
まったくない — 分割は *入力* **かつ** *契約* による。

**なぜこれが新規 ADR であり ADR-014 amendment でないか (適用された
ADR-018 Alternative-B ディスクリミネーター)。** ADR-018 の Alternatives
テーブル行 B テスト: **新しい CI ハードチェック + 新しい MECE 契約
境界 + 新しい構造的キーイング** を導入するマイルストーンは ECC 先例の
「新しい構造的決定」半分であり新規 ADR を要する。先行 ADR がすでに
予約したスロットを *埋める* マイルストーンのみがその ADR の amendment
トレールに折り込まれる。#12 のディスクリミネーターのトライアドは
**3/3** である:

1. **新しい CI ハードチェック** —
   `coverage-gate.yml`;
   既存のワークフローはカバレッジしきい値にゲートしない
   (`ci-base.yml` は **しきい値なし** でテストを実行する。4 つの
   ディテクターはカバレッジではなく Markdown 契約をチェックする)。
2. **事前予約されない新しい MECE 契約境界** — ADR-014 の §(d) MECE
   テーブル (≈ 1800 行目) は #04/#05/#09/#10/#11 を列挙する。
   #12 を **指名しない**。#12 は **事前予約スロットを占めない**。
   これは #11 との決定的な区別である。#11 は *ADR-014 §(d) がすでに
   予約したスロットを埋め* たので正しく ADR-014 amendment を取り、
   新しい ADR 番号を **消費しなかった**。#12 にはそのような予約
   スロットがないので構造的に新しい分割であり、既存分割の population
   ではない。
3. **新しい構造的キーイング** — 80% しきい値の値、その
   `.claude/CLAUDE.md` `## Testing Requirements` への信頼できる唯一の
   情報源バインディング (決定 3)、そして default-off シングルスイッチ
   アクティベーションポスチャー機構 (決定 2)。これらのキーイング
   決定のいずれも先行 ADR に存在しない。

トライアド 3/3 ⇒ **新規 ADR-019**、まさに #04/#05/#06 先例: あの
それぞれは新しいディテクター + 新しい境界 + 新しいキーイングを導入し
それぞれが *新しい* ADR (ADR-015 / ADR-017 / ADR-018) を受け取り、
#07–#11 — そのそれぞれは *事前予約された ADR-014 §(d) スロットを
埋めた* — は新しい番号を消費しない ADR-014 *amendment* だった。
019 は次の未使用番号 (016/017/018 が消費済み) である。ECC 先例の
構造的半分が ADR-015 §自己分類、ADR-017 Alternative B、ADR-018
Alternative B がそれぞれ記録したのとまったく同じく支配する。

本 ADR は決定とエージェント契約/ダウンストリームへの示唆を記録する。
それ自体はワークフロー、アクティベーション設定、しきい値抽出機構、
テストを書かず、エージェントプロンプト、Spec、いかなるテンプレート、
他のいかなる ADR、CHANGELOG、いかなる CI/スクリプトファイルも
変更しなかった — 実装は後続のセッションに委ねられ、トレーサビリティの
ために帰結 → 中立に列挙された。これは ADR-014、ADR-015、ADR-016、
ADR-017、ADR-018 が行うのとまったく同じである。これは #03/ADR-016、
#05/ADR-017、#06/ADR-018 の二セッション決定してから実装の分割先例を
継続し、単一セッション崩壊の意図的な反対であった。

## 帰結

### ポジティブ

- `## Testing Requirements` の書かれた「Minimum 80% test coverage」
  ルールが、オプトインする派生リポジトリにとって示唆ではなく
  **強制可能なビルド失敗契約** になる — Spec の主要なギャップが閉じる。
- **しきい値はちょうど 1 つの権威的ホームを持つ。** 決定 3 は CI 実行時
  に `.claude/CLAUDE.md` `## Testing Requirements` から数値を読み、
  アクティベーション設定はオン/オフスイッチのみを持ち決して数値を
  持たない。将来のしきい値変更は 1 ファイルの 1 行編集で CI/ドキュメント
  ドリフトのリスクゼロ — AC-2/AC-8/R-02 単一情報源保証が、ADR-017 §4 と
  ADR-018 §1 が使う「成果物からルールを読む」と同じ規律で実現される。
- **テンプレートは特殊ケースなしで green-by-construction。**
  default-off (決定 2) はジョブがテンプレートに対してまったく走らない
  ことを意味する。AC-5 が構造的に満たされ、不活性検出分岐 **なし**、
  カバレッジ免除 **なし**、`ref-allow` 風抑制 **なし** — Spec
  R-03/AC-5 の可能な限りクリーンな充足。
- **入力形状による言語非依存。** テンプレートはカバレッジ形式を
  パースしない (決定 4)。派生リポジトリが事前計算済みパーセンテージを
  供給し、`ci-base.yml` の `test-command` 入力をミラーする。あらゆる
  言語/ツールチェーンがテンプレート所有ロジックの変更ゼロで配線できる
  — AC-3/R-04 フォーク可能性保証。
- **`ci-base.yml` はバイト不変。** スタンドアロンファイル決定
  (決定 1) は既存の `test-command` 契約をオプトインしていない
  リポジトリにとって同一に残す — ハード制約 4 / Spec Key-interaction 1
  が構造的に満たされる。
- **MECE 分割はファミリーで最もクリーン。** #12 はまったく異なる入力
  (リポジトリ成果物ではなく実行時数値) をスキャンするので
  #04/#05/#06/#11 に対する境界が入力 *かつ* 契約で曖昧でない —
  共有サーフェス曖昧化解消が不要 (決定 5; Spec AC-6/AC-7)。
- **単一制御点はリポジトリ内で diff 可能。** CodeQL リポジトリ変数
  形状より `workaround-check.yml` スイッチ形状を選ぶことで
  アクティベーション制御を grep 可能・レビュー可能・PR diff 可能に
  保つ — AC-4 のより強い実現。

### ネガティブ

- **しきい値抽出器が `## Testing Requirements` 行形状に結合する。**
  決定 3 は `.claude/CLAUDE.md` から「Minimum NN% test coverage」を
  読む。そのセクションの文言が変わると抽出器も変わらねばならず、
  2 つを自動的に相互チェックするものはない。これは ADR-015 が引き受けた
  (`specs/NN-slug.md` にキーイング)、ADR-017 が引き受けた
  (`<br>` 結合セルと `Roadmap row: #NN` トークンにキーイング)、
  ADR-018 が引き受けた (`.ja.md` 接尾辞にキーイング) 同じ許容可能で
  絞られた結合であり、単一の最も狭いサーフェス (1 つの権威的行) に
  キーイングされた既知のメンテナンスエッジとして記録される。緩和策:
  抽出器は行が不在なら明示的メッセージで **fail-closed** する
  (決定 3) ので、結合は静かにではなく大声で壊れる。
- **default-off は未設定のフォークが何も強制しないことを意味する。**
  スイッチを決して切り替えない派生リポジトリはゲートが不活性で出荷
  される — `workaround-check.yml` が持つのと同じ受け入れられた性質。
  これはハード制約 1 (テンプレートはカバレッジ対象事項がないので
  always-on にできない) の意図的なコストである。緩和策は 1 つの文書化
  されたアクティベーションステップ (AC-4 シングルスイッチ) であり、
  コスト非対称性は意図した方向に走る: オプトインしていないフォークは
  フォークメンテナーの明示的選択であり、always-on ゲートはゼロ利益で
  初日にテンプレート自身の CI を壊す。
- **新しい分割が概念マップに加わる。** テンプレートの CI サーフェスは
  今や #04 (解決)、#05 (Roadmap インデックス一貫性)、#06 (翻訳
  パリティ)、#12 (カバレッジしきい値強制) を持つ。メンテナーはもう
  1 つの境界を保持しなければならない。緩和策: #12 の入力は他の 3 つと
  まったく素 (実行時数値 vs. リポジトリ Markdown) なので、分割は
  ファミリーで *最も* 容易に区別できる — ADR-017 が文書化しなければ
  ならなかった意図的な #04↔#05 不在 `adr:` 重複と違い、推論すべき
  重複ゾーンがない。
- **実装はひとつのセッション境界を越えて委ねられた。**
  本 ADR の設計コミットと `coverage-gate.yml`
  およびアクティベーション設定を出荷した実装セッションの間、「80%
  ルールは書かれて存在するが CI で強制されない」状態が動作上の現実
  だった (Spec R-01 末尾文)。これは二セッション分割の受け入れられた
  意図的なコストであり、#03/ADR-016、#05/ADR-017、#06/ADR-018 先例と
  同一である — 設計の正しさが実装開始前に検証され、ギャップは今や
  閉じた。

### 中立

- これは ADR-015/ADR-017/ADR-018 モールドの **CI レイヤー追加** で
  ある: エージェントは追加も削除もされない。Spec (Key-interaction
  5/6) はエージェントプロンプトの変更が不要と述べている。エージェント
  数は変わらない。
- Roadmap 行 #12 の `Design source` セルは本 ADR への `adr:` リンクを
  得た (ADR-014 の書き込みオーナーシップに従い設計セッションが実施:
  `architect` が `adr:` リンクを追加し、行 #03/#04/#05/#06 が示すとおり
  既存の予約済み `spec:` リンクの後に `<br>` で結合する)。行の Status
  グリフは設計時点では `◐ in-progress` だった — これは二セッション分割で
  あり、グリフは実装完了時に品質ゲートが通過した時点で `☑` にフリップ
  する。他の行には触れない。Roadmap フォーマットの変更なし。変更は
  インデックスのみ (単一セルの編集)。
- 正確な `workflow_call` 入力名/型、しきい値抽出 awk/grep 形式、
  sourced `.claude/meta/scripts/` ヘルパーを使うかロジックをインラインに
  するか、アクティベーション設定ファイル名と YAML キー名、ジョブ名、
  パススコープは `implementer` の詳細である。本 ADR は *構造的形態*
  (スタンドアロンファイル)、*ポスチャー* (default-off シングル
  スイッチ)、*単一情報源バインディング* (`## Testing Requirements`
  から読む、スイッチは数値を持たない)、*入力契約* (呼び出し元が測定を
  供給しテンプレートがしきい値を所有)、*MECE 分割* を固定し、bash は
  固定しない。ADR-015/016/017/018 が使った同じ中立セクション規律。
- 下流の `implementer` タスク (設計時にトレーサビリティのために記録。
  #03/ADR-016、#05/ADR-017、#06/ADR-018 の二セッション分割先例に従い
  **後続の実装セッションで実施された** — 同一セッション実装の意図的な
  反対):
  - `.github/workflows/coverage-gate.yml` —
    `workaround-check.yml` default-off 構造と `ci-base.yml`
    `workflow_call` 入力形状に従い作成する: 1 つの必須入力 (呼び出し元の
    事前計算済みカバレッジパーセンテージ、決定 4) を持つ
    `workflow_call` ワークフロー、1 つのリポジトリ内スイッチの背後で
    default-off にゲート (決定 2)、実行時に `.claude/CLAUDE.md` の
    `## Testing Requirements` を読んでしきい値を導出 (決定 3)、
    下回るとき測定カバレッジとしきい値の両方を指名するメッセージと
    非ゼロ終了で失敗 (Spec AC-1)、`permissions: contents: read`、
    `timeout-minutes: 5`、カバレッジ失敗を曖昧でなく示す決定的な
    ジョブ名 (Spec AC-1、ターゲットユーザー orchestrator/test-runner)。
  - ちょうど 1 つの `enabled` 風ブール値を持ち **しきい値数値を持たない**
    単一のリポジトリ内アクティベーション設定成果物 (決定 2/3)、
    `workaround-check.yml` / `.github/workaround-tracker.yml` シングル
    スイッチ形状。ファイル名/キーは既存ファミリー規約の下での
    `implementer` のもの。
  - インラインステップが不十分と implementer が判断する場合 *に限り*
    `.claude/meta/scripts/` 配下の小さなしきい値抽出ヘルパー (決定 1) —
    その存在とパスは `implementer` のもの。本 ADR はそれを義務付けも
    禁止もしない。
  - テスト — `test-check-*.sh` 規約に従い作成する: (a) しきい値以下の
    カバレッジが測定値 + しきい値を指名して FAIL すること、
    (b) しきい値以上のカバレッジが通過すること、(c) スイッチオフが
    ジョブを不活性にすること (テンプレート green-by-construction、
    Spec AC-5)、(d) `## Testing Requirements` 権威的行の欠如が
    fail-closed すること (決定 3)、(e) しきい値が変更された
    `## Testing Requirements` 値に第 2 の編集なしで追従すること
    (Spec AC-2/AC-8)、(f) `ci-base.yml` と 4 つのディテクター
    スクリプト + 3 つのテストスイートがバイト不変であること
    (Spec AC-6) を証明するフィクスチャ。
  - 本 ADR の日本語版 (`019-coverage-ci-gate.ja.md`) は **本同一
    セッションで** `architect` が作成する (新規 ADR の JA ミラーは
    architect のものであり `technical-writer` に委ねられない)。
    ADR-017 と ADR-018 の JA 兄弟がその EN オリジナルとともに作られた
    のとまったく同じ。見出しツリーパリティ (level + position) が
    必須でありこのセッションで検証される。
- エージェントプロンプトの変更は導入も示唆もされない。Spec の
  Key-interaction 5/6 がゲートは CI レイヤーのみと述べている。

## 反対提案

深刻な反対立場は **新規 ADR-019 + 新しいスタンドアロンワークフローの
代わりにカバレッジゲートを ADR-014 amendment に折り込み `ci-base.yml`
を拡張する** (代替案 B + A を単一の「最小フットプリント」立場に統合)
である。ADR-012 / ADR-014 / ADR-015 / ADR-016 / ADR-017 / ADR-018 の
先例 — strawman としてではなく却下された代替案を真剣に扱う — に従い
ここに記録する。これは ADR-017 の Alternative A と ADR-018 の
Alternative A (新しいチェックを既存のものに折り込む) を ADR-017 の
Alternative B (新しい ADR 番号なし) と交差させた直接の類似である。
論点、最大の強さで:

1. **ADR 番号が少ない、最近のハウスパターン。** #07 から #11 は
   *すべて* ADR-014 amendment であり新しい ADR 番号を **ゼロ** 消費
   した。#12 の amendment はその最近の流れを継続し ADR インデックスを
   コンパクトに保つ。新しい ADR 番号は永続的な概念的重みを運ぶ。
   作らないのが保守的な既定。
2. **`ci-base.yml` はすでにテストを実行する。** 再利用可能ワークフロー
   はすでに `test-command` を受け取り派生リポジトリのスイートを実行
   する。カバレッジ数値はまさにその実行で生成される。データを既に持つ
   ワークフローに `coverage-threshold` 入力と 1 つの比較ステップを
   追加するのは、独自の `workflow_call` インターフェース、
   アクティベーションスイッチ、しきい値抽出ロジックを持つ第 2 の
   ワークフローファイルを立てるより可動部品が少ない — 1 ワークフロー、
   1 オーナー、見るべき 1 か所。
3. **1 ワークフロー、1 オーナーが最も単純な構造。** ディテクター
   ファミリー ADR 自身が繰り返し locality-of-behavior を持ち出す。
   単一のカバレッジ対応 `ci-base.yml` は「テストしてゲートする」物語を
   メンテナーが心的に結合せねばならない 2 ワークフローに分割するのでは
   なく 1 ファイルに保つ。

**反対提案が採用されなかった理由:**

- **ディスクリミネータートライアドが 3/3 で構造的半分が支配する。**
  ADR-018 の Alternative-B テストは「新規 ADR vs. amendment」を
  マイルストーンが新しいチェック + 新しい MECE 境界 + 新しいキーイングを
  導入するかで分類する。#12 は 3 つすべてを満たす (決定 5): 新しい
  CI ハードチェック
  (`coverage-gate.yml`;
  今日カバレッジにゲートするものはない)、**ADR-014 §(d) のテーブルが
  事前予約しない** 新しい MECE 分割 (#04/#05/#09/#10/#11 を指名し
  #12 ではない)、そして新しい構造的キーイング (80% の値 + その単一
  情報源バインディング + アクティベーションポスチャー)。ADR-015、
  ADR-017、ADR-018 がそれぞれ同一の形 (新しいチェック + 新しい境界 +
  新しいキーイング) を amendment **ではなく** 新規 ADR と自己分類した。
  amendment 反対の前提 — 「これは既存 ADR の帰結明確化」 — は偽である:
  これが帰結を明確化する先行 ADR は存在しない。
- **#11 は #12 の先例としてではなく反対の理由で amendment を取った。**
  #07–#11 が amendment だったのは **そのそれぞれが ADR-014 §(d) が
  すでに予約したスロットを埋めた** からである — それらは *既存分割の
  population* であり、教科書的な amendment ケース。#12 は **どの**
  事前予約 §(d) スロットも埋めない (テーブルは #12 を名前で省く)。
  それは分割を *作る*。#07–#11 の amendment の流れを #12 のパターンと
  して引用することは実際のルールを逆転させる: ルールは「最近の
  amendment 数」ではなく「事前予約スロット?」にキーイングする。実際の
  ルールでは #12 は新規 ADR であり #11 は一貫した反対の理由で
  amendment だった。
- **`ci-base.yml` の拡張は 2 つの契約を混在させ Key-interaction 1 を
  破る。** `ci-base.yml` は「派生リポジトリの `test-command` を実行」
  を所有する — すべての呼び出し元がすでに **しきい値なし** で依存する
  契約。カバレッジゲートを接ぎ木すると「テストは走ったか?」と
  「カバレッジ ≥ しきい値か?」を 1 名前の 1 ジョブに乗せ (ADR-017 §2 と
  ADR-018 §5 が却下したまさにその曖昧さ) **かつ** オプトインしていない
  すべての呼び出し元にしきい値の意見を継承させ、Spec Key-interaction 1
  / ハード制約 4 (「既存の `test-command` 挙動はオプトインしていない
  派生リポジトリで不変でなければならない」) を破る。default-off は
  そのとき共有ジョブ *内部* の `if:` ガードを要する — AC-4 が明示的に
  禁じる第 2 ガードアンチパターン。「可動部品が少ない」利点は本物だが
  2 つの拘束的 Spec 制約を破ることで買われる。スタンドアロンの
  `workflow_call` ファイルは 2 つの契約を 2 つのオーナーに保ち
  `ci-base.yml` をバイト不変に残す。
- **反対が買う単純さは契約レベルで幻想的。** 「1 ワークフロー」が
  単純なのは 2 つの契約が 1 つだった場合のみ。それらは違う:
  「テストを実行」は無条件でオプトイン不要、「カバレッジにゲート」は
  オプトインでしきい値を運ぶ。それらを崩すのは ADR-012 が dispatcher
  に、ADR-015 が Alternative C に、ADR-017 が Alternative A に、
  ADR-018 が Alternative A に適用したのと同じ locality-of-behavior の
  誤りである — Spec が意図的に引いた分離を「単純化して消す」ために
  より大きな正しさのコスト (壊れた Key-interaction 1、混在ジョブ、
  禁じられた第 2 ガード) を払う。

**この反対提案を再評価するトリガー条件:**

- ADR-014 の §(d) MECE テーブルが再構築され **カバレッジ強制スロットを
  追加** する (すなわち ADR-014 が #12 が今作る分割を事前予約する)。
  その時点で #12 は事前予約スロットを埋めることになり、本 ADR が適用
  するまさにそのディスクリミネーターの下でスタンドアロン ADR-019 では
  なく ADR-014 amendment が正しい分類になる。
- `coverage-gate.yml`
  と `ci-base.yml` が実装時に YAML (ジョブスキャフォールド、チェック
  アウト、`workflow_call` 配管) を多く共有し、マージされたワークフロー
  ではなく両方が source する **共有 composite アクション** が正しい
  リファクタリングになることが判明する。これは二契約分割を保ちながら
  重複を取り除く。ADR-017 と ADR-018 がディテクターファミリーに記録した
  「マージされたスクリプトではなく共有ライブラリ」と同じ再評価トリガー。
- 「Minimum 80% test coverage」ルールが `.claude/CLAUDE.md`
  `## Testing Requirements` から完全に **削除** される (例: テンプレート
  がカバレッジ下限を義務付けなくなる)。強制される契約の対象事項が
  そのとき消え、subject-matter-presence ルール自身がゲートを retire
  または reclassify する — その時点で反対だけでなく本 ADR 全体が
  再評価される。

反対提案は ADR-012 / ADR-014 / ADR-015 / ADR-016 / ADR-017 / ADR-018
の規約に従い、決定の最も深刻な異議の歴史的記録として本 ADR に残る。
代替 ADR ファイルは作成されない — 却下された反対の正しい状態は
非存在であり、本 ADR-019 ファイルがその唯一の引用可能なホームである。

注記: 設計時、当時まだ作成されていない実装成果物 (`coverage-gate.yml`
と計画中の `.claude/meta/scripts/` ヘルパー) を参照する行に
`<!-- ref-allow: -->` 抑制が置かれていた。対象は **本 ADR ファイル**
(`.claude/meta/adr/019-coverage-ci-gate.md`) とその JA 兄弟に
**限定** され、`specs/12-coverage-ci-gate.md`、
`specs/11-verification-domain-opt-in-guidance.md`、
`specs/05-roadmap-drift-detection-ci.md` が設定した先例に従った。
これらの抑制は成果物が具体化した際に **削除** された (#11 LOW
先例: 前方参照が解消したときの過剰抑制除去)。
それらは `.claude/CLAUDE.md` には **現れなかった**。
